## 一、一句话定位

给 agent 用的**本地长期记忆**：跨会话记住经验、决策、事实、偏好，按语义检索并注入上下文。
纯本地、零 GPU、无 torch、单文件 SQLite、约 220 MB。

---

## 二、架构（五层管线）

```
① 候选层  candidates  语义 top-30 ∪ 图扩展(2跳,每节点top-5,上限20)
② 打分层  score_base  0.50 content + 0.20 tags + 0.15 keyword(BM25) + 0.15 graph
③ 排序层  rank        decay × trust 作乘数；两遍分母(无图 /0.85，有图 /1.00)
④ 选择层  select_flat 冷区过滤、draft 过滤、token 预算
⑤ 渲染层  render      截断(65%头+35%尾)、签名提取、来源标注
```

**存储**：`mem_items` / `mem_events` / `mem_edges` / `mem_sessions` / `mem_graph_meta` / `identity`，向量存 BLOB。

### 三通道设计（2026-11-09 完成）

| 通道 | 触发 | 实现 |
|---|---|---|
| **注入** push | 每轮 | stable→`sections.mem`（缓存零损失）、tail→`message` |
| **总结** harvest | ①压缩前 ②≥60K token ③≥10 轮且新增≥2K | tail 末尾追加一行提示，不额外开一轮 |
| **检索** pull | 模型自行判断 | `mem_search(query, k)` 工具 |

**触发阈值依据**（本会话实测 123 轮 / 453K token / 平均 3.7K 每轮）：

| 参数 | 值 | 理由 |
|---|---|---|
| 首次 token | 60K | 128K 窗口一半；实测第 7 轮就 16.8K，第 20 轮约 70K |
| 再触间隔 | +40K | 60K → 100K → 140K |
| 轮次 | 10 轮 | 生活对话 10 轮约 2K token，够提炼偏好 |
| 轮次下限 | 新增 ≥2K token | 防止 10 轮寒暄后强制总结产出垃圾 |

### 常驻服务（2026-11-09 完成）

**不做开机自启、不做后台常驻**——服务是 pi 的子进程，跟着 pi 生、跟着 pi 死。

| 机制 | 触发 | 行为 |
|---|---|---|
| `session_shutdown` | 退出 / 重载插件 | 显式 kill |
| stdin 管道 EOF | pi 崩溃 / 被强杀 | 服务 `os._exit(0)` |
| 空闲超时 | 1 小时无请求 | 自动退出 |

**降级**：服务拉不起来 → 自动回退到每次起子进程（900ms），功能不受影响。

| 项 | 起子进程 | 常驻服务 |
|---|---|---|
| 单轮延迟 | ~900 ms | **8–20 ms** |
| 预热 | 每轮 | 每会话一次 |

**实测**：`daemon_start → 轮1 20ms → 轮2 15ms → 轮3 8ms → shutdown(quit) → 服务已关闭 ✓`，无孤儿进程。

**成本**（100 轮 / 10 次总结）：

| 项 | token |
|---|---|
| tail 注入 | 28K（未命中价） |
| stable 注入 | 85K（命中价） |
| harvest 提示 + 写记忆 | 0.9K + 4.5K 输出 |

≈ **$0.015 / 100 轮 ≈ 1 毛钱**。真正的成本是延迟 ~900 ms/轮。

**三个专项全部通过**：
- scope 泄漏：无（A 项目的记忆不会被 B 召回）
- 断言区分度：`verified=2` 的工具实证压过 `verified=0` 的旧断言 ✅

**测出并修掉的根因：窄带归一化**

失败案例：「三个库的数据结构是统一的吗？」→ 期望条目纯语义排 **第 1**（sim 0.8900），最终排 **第 9**。

原因：e5 中文相似度压在 0.84–0.89 窄带，`W_CONTENT×sim` 的方差只有 0.03，
而 tags/keyword 覆盖率能贡献 0.1+ —— **排序被关键词主导，语义白算**。

修法：候选内 min-max 归一化，`sim = 0.5×raw + 0.5×norm`，span < 0.02 时不归一（防放大噪声）。

**合成集同样验证**（1997 条，30 查询）：Hit@1 23.3%→26.7%，Hit@3 50%→66.7%，Hit@10 90%→100%。

| top_n | 语义候选 | + 2 跳扩展 |
|---|---|---|
| 3 | 3 | **23**（+20，撞 max_add 上限） |
| 10 | 10 | **28**（+18） |
| 30 | 30 | **39**（+9） |

57 条时图扩展终于有货了（13 条时 +0）。印证"扩展只在 scope > top_n 时生效"。

质量：Hit@1 85% / Hit@3 100% / MRR 0.910（35 条时 85/92/0.900）——加 22 条真实记忆后 Hit@3 回到 100%、MRR 上升。说明高价值记忆不稀释，只有噪音才稀释（对方实测：注入 20 条通用常识让召回 11/14 → 10/14）。

### 这个测试的可信度（自我批评）

| 问题 | 影响 |
|---|---|
| n=13，一个查询 = 8 个百分点 | 统计上不显著 |
| 查询是我写的，措辞贴近记忆原文 | **乐观偏差** |
| 归一化参数在同一批查询上调 | 有过拟合风险（合成集独立验证缓解了一部分） |
| 没有负样本 | 不知道"该返回空时会不会硬凑" |
| 没有噪音率 | 不知道 top-3 里有几条无关 |

**要变成可信的尺子，需要**：查询由用户写、样本 ≥50、加负样本（应返回空）、人工标注 top-3 相关性。

### 图扩展参数对照（vs memctx 原插件）

| 参数 | memctx 原插件 | 现在 | 评价 |
|---|---|---|---|
| 种子数 | `pprSeeds=5` | `expand_seeds=5` | 一致 |
| 每节点出边 | `topK=5`（行为共现边） | `GRAPH_TOP_K=5`（相似度边） | 一致 |
| 逐跳衰减 | `pprDamping=0.85` | `GRAPH_HOP_GAMMA=0.85` | 一致 |
| 图打分 | `max` 或 **PPR**（两模式） | `max(w × base)` 单模式 | 我们没做 PPR |
| 扩展跳数 | PPR 隐式传播 | 显式 2 跳 BFS | 不同 |
| 扩展总量 | 无硬上限（靠阻尼收敛） | `max_add=20` | 我们更硬 |
| 矛盾边 | — | 每节点 5 条 | 新增 |

**实测跳数分布**（1997 条，语义 top5 做种子）：

```
种子 5 + 第 1 跳 2 条（strength 0.84）+ 第 2 跳 8 条（strength 0.71）= 15 条
max_add=20 根本没撞到
```

**瓶颈不是 max_add，是 `per_node=5` + `seen` 去重**。图稀疏时第 1 跳常常只出 2 条。
评审建议的 `K=[50,30,20,10,5]` 逐跳 beam 比我们宽一个数量级——要不要放宽，等记忆质量测试有了尺子再定。

## 八、不可动摇的决策

| 决策 | 理由 |
|---|---|
| SQLite 而非 LanceDB | 启动 248ms vs 1839ms |
| ONNX int8 而非 torch | 启动 355ms vs 9396ms，省 4GB |
| 不做 content 归一化 | 原作者 BM25 混合盲测失败（8-9 分） |
| 不做同义边 | 几何不可区分，用 near_dup 替代 |
| 边存 SQLite 表 | 避开"邻接表文件名不带 hash 被覆盖"事故 |
| `retrieve` 只返回 JSON | 不假设宿主形态 |
| 重锚只写尾部 | 改 system 会让前缀缓存全废 |

## 0. 一句话现状

ΠMem（`pi-package/mem.py`）**只做前台**：每轮一个钩子进出，写入、摘要、冲突比对、推翻全部由主模型完成；
后台的 harvest / L2 / daemon 守护已物理删除。检索质量 **Hit@1 85% / Hit@3 100% / MRR 0.910**（快照尺子）。

## 1. 架构：从"前后台双路"改为"只有前台"

### 1.1 为什么推翻

前后台并用需要协调"谁能推翻谁、谁先写、冲突谁负责"，五个小时没理清；且后台切片永远拿不到跨段语境，
`赞同/可以` 类省略句无法还原。**维护成本 > 收益。**

### 1.2 新架构（一个入口，四条通道，串行）

```
每轮开始  hook（读）
   A persistent + working   同一次 retrieve，共用嵌入器
   B kb      默认 off（MEM_KB=1）
   C focus   默认 off（MEM_FOCUS=1，独立 focus.db）
   ↓ system（永不变化：stable 8 条） / tail（每轮变化）
每轮结束  mem_turn_close（写）
   收口 → 摘要落盘 → 提升 decision/rejected → 返回冲突候选
发现矛盾  mem_supersede（写）
   新陈述写入(origin=user, v1) → 旧条 superseded + replaces 边
关窗      segment finalize --no-enrich（只本地收口，不调 LLM）
```

**串行**，不并行：避免并发 debug 成本；`lanes` 字段逐路报状态，单路失败只降级自己。

### 1.3 已删除（不要找回来）

| 删掉 | 原位置 |
|---|---|
| 关窗 harvest 入队 + `pending.json` + 下次启动补跑 | memskill.ts |
| 压缩前 harvest 提醒 + `[mem:harvest]` 两种提示 | memskill.ts |
| `dumpTranscript / spawnHarvest / lastHarvest / harvestCmd / harvestLine` | memskill.ts |
| 关窗 L2 enrich | `finalize --no-enrich` |

`memskill.ts` 1123 → 931 行。`mem.py` 的 `harvest` / `enrich` CLI 只保留给手动修复。

| 接口 | 形态 | 用途 |

## 5. 设计原则（不要违反）

1. **统一钩子**：所有记忆能力挂同一个每轮入口，不为某个功能另开后台进程/守护。
2. **缓存分区**：永不变化的进 system（字节不变才重写）；会变化的进 tail；写入载荷只落盘，回执一行。
3. **四个库共用入口，不共用表**：`mem.db`（持久+工作）、`focus.db`（注意力）、知识库（LanceDB）各自独立。
4. **工作记忆 ≠ 持久记忆**：段只存指针+摘要，结论要进持久记忆必须过门槛；原文留 JSONL，用 `first_id/last_id` 指过去。
5. **相对路径**：代码零绝对路径；数据在 `MEM_HOME`，可用 `MEM_HOME/MEM_DB/MEM_CONFIG/MEM_MODEL/MEM_PY_PATH` 覆盖，整目录可拷走。
6. **单模型**：全机只跑 e5-small 384 维，记忆库必须复用它（换模型必须重测全部阈值）。
7. **项目名由 LLM 自己判断**：只对「项目级常识」（本项目专属的参数/阈值/路径/约定/技巧）加项目名；
   通识（语言特性、算法原理、库的通用用法）不加。判断标准一句话：**换个项目还成立吗？成立就不加**。

### 模型生命周期（2026-11-10 定稿）

```
会话开始：健康检查不通 → 拉起 serve（不阻塞，顺便预热模型）
任何时候：请求走 HTTP；失败 → 该次退回 spawn（不断链）
空闲 15 分钟：python 自己退出（--idle-timeout 900）
会话结束：adapter 什么都不做（只收口，不 kill）
```

**为什么不"会话结束就 kill"**：pi-web 可能同时开 3 个会话，要正确 kill 必须引入跨会话
引用计数（锁或 pid 台账）→ 多一层，只为早释放约 120MB。空闲自退能覆盖 99% 场景。

**冷掉再复活会失效吗**：不会。daemon 只是"已加载模型的缓存"，状态全在 SQLite。
复活后第一轮若 daemon 已退，健康检查失败 → 自动拉起（或该次退回起进程），
代价只是多 1.4 秒，结果正确。为防端口被别的 `MEM_HOME` 的 daemon 占着，
`/health` 返回 `home`，adapter 比对不一致就不用这个 daemon。

## 6. Hooks / 坑（本次新增）

0. **`turn_start/turn_end` 会倒挂**：压缩后宿主的轮次计数回退（实测 `seg-db69d8`
   `23→2`），旧代码直接落库。现在两层防护：`_seg_close` 落库前 `t_end = max(..., t_start)`；
   历史脏数据用 `python mem.py segment repair-turns [--apply]` 按段自带的
   `first_id/last_id` 回原文重定位（默认只预演，写库记 `mem_events.action=repair_turns`）。
   `last_id` 锚点丢失时只能修到 `turn_start`（宁可不猜）。

1. **孤儿段（transcript 为空）可以回填**：`python mem.py segment repair-transcript [--apply]`
   按 `session_id` 在 `~/.pi/agent/sessions` 里找唯一原文，核对 `turn_end` 不超界后写入，
   记 `mem_events.action=repair_transcript`。回填后 `enrich` 立刻可用（本次 5 条全部补出摘要，
   Hit@1 60.9→65.2、MRR 0.750→0.772）。

2. **常驻 daemon 会一直跑旧代码**：`mem.py serve` 15:22 起，16:12 改的打分权重不生效，
   表现为"注入的段 id 与当前代码算的不一致、也没有〔旧会话〕标记"。已加护栏：
   `/health` 返回 `py_mtime` 与 `home`，adapter 发现常驻进程比磁盘旧就 `/shutdown`
   （老版本无此路由则按 pid 收掉）再起新的；收不掉就本轮退回起进程，不空转。
   改 `mem.py` 后**不需要重启宿主**，下一轮自动换新进程。


1. **`node --check` 与 strip-types 抓不到"用了未声明变量"**。`commitNudged` 漏声明就是每轮抛 ReferenceError。
   → 改 handler 后跑一次假宿主 harness（`/tmp/hz/harness.mts` 模式），真调用 `session_start → before_agent_start ×3 → mem_turn_close`。
2. **自测会污染排序**：`activation.boost` + 衰减用 `last_hit` → 同一 query 反复查会把旧条目顶上去。
   → 测试/调参用 `search --no-activate`；评测用 `eval_mem.py --snapshot`（独立 `evalbench` scope，刷新时间戳）。
3. **评测必须用快照**：直接跑 `global` 会随库长大而掉分（62%），快照后是 85%/100%/0.910。
4. **`CHARS_PER_TOKEN=3.3` 低估中文约 1.9 倍**（实测 1.73 字符/token），`n_tokens()` 还被 256 截断。
5. **pi-web 不热重载扩展**：改 `.ts` 必须 `pi-web stop` 重启；关标签页不触发 shutdown（空闲 10 分钟才 destroy）。

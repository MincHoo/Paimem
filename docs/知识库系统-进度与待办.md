## 三、待办

### P0 · 英文建库决策（阻塞中）

39.57M 块需 **29 小时 GPU + 79 GB 磁盘**，当前磁盘只剩 44 GB。三个选项：

| 方案 | 块数 | 工时 | 磁盘 | 说明 |
|---|---|---|---|---|
| A. 提阈值到 ≥5000 token | ~1600 万 | 12 h | 32 GB | 推荐 |
| B. 提阈值到 ≥8000 token | ~900 万 | 7 h | 18 GB | 更省，召回略降 |
| C. 只取部分分片 | 自定 | 自定 | 自定 | 质量不均 |
| D. 维持现状不建 | 0 | 0 | 0 | 英文查询只能靠中文库 |

**决定后**：重切 en → 建库 → 删 `数据/raw/`（省 46 GB）

### P1 · 修代码字节/字符偏移

`chunk_code_v3.py` 里 `code[s:e]` 把 AST 的**字节偏移当字符偏移**用。含中文注释的文件会切错，约 4% 受影响。

修法：`raw[:s].decode()` 转字符索引。
代价：重切 code（1h）+ 重建索引（1h）。

### P2 · 打包分发

## 四、关键决策

| 决策 | 理由 |
|---|---|
| **建库用 torch fp16 GPU** | 450 chunk/s；ONNX CPU 只有 35/s，550 万块要 43 小时 |
| **查询用 ONNX fp32** | 索引是 torch fp16 建的；int8 查询向量 cos 0.99 但 **top-10 重合度只剩 70%** |
| **父子分块** | 子块检索（384 token）、父块返回（上下文完整） |
| **全离线可溯源** | 每条带 url + license |
| **与记忆库完全解耦** | 依赖/生命周期/权限都不同 |

## 五、踩过的坑

| 坑 | 后果 | 解法 |
|---|---|---|
| e5 必须加前缀 | 漏了「快速排序」返回 Cron | `passage: ` / `query: ` |
| finewiki 分片有重复页 | 中文 4 万行重复 page_id | 按 parent_id 去重 |
| `ls out/cc_*.parquet` | 把 cc_en 也算进来，parents/children 不匹配 | 精确 glob |
| 跳过逻辑只看文件大小 | 残缺 parquet 被跳过 | 校验 footer |
| `xargs -P 6` | GPU 建库 tokenizer 被饿死（380→74/s） | 最多 2 进程 |
| 代码语言字段大写 `"GO"` | 写 `"Go"` 静默丢光 Go 文件 | — |
| `lexical_declaration` 噪音 | chunk 数虚高 | 移除后降 16% |
| tree-sitter JS 死循环 | 卡在 `TextInput.js` | JS/TS 加 30KB 上限 |
| 分片 12 卡死 | code 切块中断 | 已修复，17/17 完整 |
